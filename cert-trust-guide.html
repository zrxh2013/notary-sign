一、适用场景与证书现状

本平台当前使用自签 HTTPS 证书（未使用付费/免费 CA 签发的正式证书），因此浏览器首次访问时会提示「连接不是私密连接」。这是自签证书的正常现象，按下方步骤处理即可。

项目内容
证书文件/workspace/certs/cert.pem（可公开分发）
私钥文件/workspace/certs/key.pem（严禁外传）
证书主题CN = localhost, O = XinQianYun Notary
证书 SANDNS:localhost、IP:127.0.0.1
有效期2026-11-02 ~ 2027-11-02（1 年）
SHA-256 指纹FA:92:A7:8C:43:53:A9:23:F0:3F:E4:74:04:75:AD:6C:3D:A4:15:2D:BE:70:DC:0A:DF:1C:B5:27:F8:FD:A3:0D
关键认知：证书是否「有效」，取决于访问地址是否在证书的 SAN（备用名称）列表里。当前证书只覆盖 localhost 和 127.0.0.1，因此本机访问无需安装证书；若要从其他设备或局域网 IP 访问，必须先重新生成包含该 IP 的证书（见 4.2 节）。

二、启动服务

1
在服务器上启动 HTTPS 服务
# 进入项目目录
cd /workspace

# 启动服务（监听 0.0.0.0:8090，仅 HTTPS）
node server.js

启动成功后终端会输出：

[OK] 信签云 HTTPS 服务已启动，监听 0.0.0.0:8090
[OK] 访问入口: https://localhost:8090/index.html

如需后台常驻运行：

nohup node server.js > /tmp/notary-https.log 2>&1 &
营业时间闸门：首页默认仅在北京时间 09:00–21:00开放。非开放时段会显示休息页与倒计时。演示或调试时可在地址后加 ?force=1 绕过，例如 https://localhost:8090/index.html?force=1。

三、本机访问（无需安装证书）

2
在服务器本机浏览器打开并接受警告

访问地址：https://localhost:8090/index.html

浏览器会提示「您的连接不是私密连接」，按下面方式继续：

浏览器操作路径
Chrome / Edge点击「高级」→「继续前往 localhost（不安全）」
Firefox点击「高级…」→「接受风险并继续」
Safari点击「显示详情」→「访问此网站」
为什么可以放心继续：该证书由本服务自行生成，浏览器报警仅表示它不是公共 CA 签发，并不代表连接被第三方劫持。本机访问时流量不经过外网。

四、其他设备信任证书

4.1 导出可分发证书文件

把 PEM 转为 Windows / Android / iOS 更易识别的 DER 格式（扩展名 .cer）：

openssl x509 -in /workspace/certs/cert.pem -outform der -out /workspace/certs/cert.cer
安全红线：只分发 cert.cer 或 cert.pem。绝不可把 key.pem 交给任何人——私钥泄露等同于证书被冒用。

4.2 先确认访问地址是否在证书 SAN 内

若从局域网另一台设备访问（如 https://192.168.1.20:8090），当前证书不包含该 IP，即使安装了证书也会报「证书名称不匹配」。需重新生成证书并加入该 IP：

openssl req -x509 -newkey rsa:2048 \
  -keyout /workspace/certs/key.pem \
  -out /workspace/certs/cert.pem \
  -days 365 -nodes \
  -subj "/CN=192.168.1.20/O=XinQianYun Notary" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.1.20"

把 192.168.1.20 替换为服务器的实际局域网 IP（Linux 用 hostname -I 或 ip addr 查看）。生成后需重启服务，并重新把新 cert.cer 装到各设备。

4.3 Windows

1. 将 cert.cer 拷贝到目标电脑，双击打开。

2. 点击「安装证书」→ 选择「本地计算机」（需管理员权限）。

3. 选择「将所有证书放入下列存储」→ 浏览 → 选择「受信任的根证书颁发机构」→ 确定 → 完成。

4. 关闭并重新打开浏览器。

若误装到「个人」存储，浏览器仍会报警。可在 certlm.msc 中检查证书是否位于「受信任的根证书颁发机构 → 证书」下。

4.4 macOS

1. 双击 cert.cer，钥匙串访问会提示添加，选择「系统」钥匙串。

2. 在钥匙串访问中找到该证书，双击打开。

3. 展开「信任」→「使用此证书时」选择「始终信任」→ 关闭窗口并输入管理员密码。

也可用命令行一步完成：

sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  /workspace/certs/cert.cer

4.5 Linux

Debian / Ubuntu 系：

sudo cp /workspace/certs/cert.pem /usr/local/share/ca-certificates/xinqianyun.crt
sudo update-ca-certificates

CentOS / RHEL 系：

sudo cp /workspace/certs/cert.pem /etc/pki/ca-trust/source/anchors/xinqianyun.crt
sudo update-ca-trust

Firefox 使用独立的证书库，需额外导入：设置 → 隐私与安全 → 证书 → 查看证书 → 证书颁发机构 → 导入。

4.6 Android

1. 将 cert.cer 传到手机（微信文件传输、邮件附件或数据线均可）。

2. 设置 → 安全（或「密码与安全」）→ 加密与凭据 → 安装证书 → CA 证书 → 选择下载的 cert.cer。

3. 系统会提示「您的数据可能不安全」，确认继续并输入锁屏密码。

不同厂商路径略有差异：小米在「密码与安全 → 系统安全 → 加密与凭据」；华为在「安全 → 更多安全设置 → 加密和凭据」；OPPO/vivo 在「安全 → 更多 → 系统安全」。
