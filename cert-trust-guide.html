一、适用场景与证书现状

本平台当前使用自签 HTTPS 证书（未使用付费/免费 CA 签发的正式证书），因此浏览器首次访问时会提示「连接不是私密连接」。这是自签证书的正常现象，按下方步骤处理即可。

项目内容
证书文件/workspace/certs/cert.pem（可公开分发）
私钥文件/workspace/certs/key.pem（严禁外传）
证书主题CN = localhost, O = XinQianYun Notary
证书 SANDNS:localhost、IP:127.0.0.1
有效期2026-11-02 ~ 2027-11-02（1 年）
SHA-256 指纹FA:92:A7:8C:43:53:A9:23:F0:3F:E4:74:04:75:AD:6C:3D:A4:15:2D:BE:70:DC:0A:DF:1C:B5:27:F8:FD:A3:0D
关键认知：证书是否「有效」，取决于访问地址是否在证书的 SAN（备用名称）列表里。当前证书只覆盖 localhost 和 127.0.0.1，因此本机访问无需安装证书；若要从其他设备或局域网 IP 访问，必须先重新生成包含该 IP 的证书（见 4.2 节）。

二、启动服务

1
在服务器上启动 HTTPS 服务
# 进入项目目录
cd /workspace

# 启动服务（监听 0.0.0.0:8090，仅 HTTPS）
node server.js

启动成功后终端会输出：

[OK] 信签云 HTTPS 服务已启动，监听 0.0.0.0:8090
[OK] 访问入口: https://localhost:8090/index.html

如需后台常驻运行：

nohup node server.js > /tmp/notary-https.log 2>&1 &
营业时间闸门：首页默认仅在北京时间 09:00–21:00开放。非开放时段会显示休息页与倒计时。演示或调试时可在地址后加 ?force=1 绕过，例如 https://localhost:8090/index.html?force=1。

三、本机访问（无需安装证书）

2
在服务器本机浏览器打开并接受警告

访问地址：https://localhost:8090/index.html

浏览器会提示「您的连接不是私密连接」，按下面方式继续：

浏览器操作路径
Chrome / Edge点击「高级」→「继续前往 localhost（不安全）」
Firefox点击「高级…」→「接受风险并继续」
Safari点击「显示详情」→「访问此网站」
为什么可以放心继续：该证书由本服务自行生成，浏览器报警仅表示它不是公共 CA 签发，并不代表连接被第三方劫持。本机访问时流量不经过外网。

四、其他设备信任证书

4.1 导出可分发证书文件

把 PEM 转为 Windows / Android / iOS 更易识别的 DER 格式（扩展名 .cer）：

openssl x509 -in /workspace/certs/cert.pem -outform der -out /workspace/certs/cert.cer
安全红线：只分发 cert.cer 或 cert.pem。绝不可把 key.pem 交给任何人——私钥泄露等同于证书被冒用。

4.2 先确认访问地址是否在证书 SAN 内

若从局域网另一台设备访问（如 https://192.168.1.20:8090），当前证书不包含该 IP，即使安装了证书也会报「证书名称不匹配」。需重新生成证书并加入该 IP：

openssl req -x509 -newkey rsa:2048 \
  -keyout /workspace/certs/key.pem \
  -out /workspace/certs/cert.pem \
  -days 365 -nodes \
  -subj "/CN=192.168.1.20/O=XinQianYun Notary" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.1.20"

把 192.168.1.20 替换为服务器的实际局域网 IP（Linux 用 hostname -I 或 ip addr 查看）。生成后需重启服务，并重新把新 cert.cer 装到各设备。

4.3 Windows

1. 将 cert.cer 拷贝到目标电脑，双击打开。

2. 点击「安装证书」→ 选择「本地计算机」（需管理员权限）。

3. 选择「将所有证书放入下列存储」→ 浏览 → 选择「受信任的根证书颁发机构」→ 确定 → 完成。

4. 关闭并重新打开浏览器。

若误装到「个人」存储，浏览器仍会报警。可在 certlm.msc 中检查证书是否位于「受信任的根证书颁发机构 → 证书」下。

4.4 macOS

1. 双击 cert.cer，钥匙串访问会提示添加，选择「系统」钥匙串。

2. 在钥匙串访问中找到该证书，双击打开。

3. 展开「信任」→「使用此证书时」选择「始终信任」→ 关闭窗口并输入管理员密码。

也可用命令行一步完成：

sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  /workspace/certs/cert.cer

4.5 Linux

Debian / Ubuntu 系：

sudo cp /workspace/certs/cert.pem /usr/local/share/ca-certificates/xinqianyun.crt
sudo update-ca-certificates

CentOS / RHEL 系：

sudo cp /workspace/certs/cert.pem /etc/pki/ca-trust/source/anchors/xinqianyun.crt
sudo update-ca-trust

Firefox 使用独立的证书库，需额外导入：设置 → 隐私与安全 → 证书 → 查看证书 → 证书颁发机构 → 导入。

4.6 Android

1. 将 cert.cer 传到手机（微信文件传输、邮件附件或数据线均可）。

2. 设置 → 安全（或「密码与安全」）→ 加密与凭据 → 安装证书 → CA 证书 → 选择下载的 cert.cer。

3. 系统会提示「您的数据可能不安全」，确认继续并输入锁屏密码。

不同厂商路径略有差异：小米在「密码与安全 → 系统安全 → 加密与凭据」；华为在「安全 → 更多安全设置 → 加密和凭据」；OPPO/vivo 在「安全 → 更多 → 系统安全」。

4.7 iOS / iPadOS（需两步，缺一不可）

第一步 · 安装描述文件

1. 通过 AirDrop、邮件附件，或直接用 Safari 从本服务下载 cert.cer。

2. 设置 → 通用 → VPN 与设备管理（或「已下载描述文件」）→ 点击该描述文件 → 安装 → 输入锁屏密码 → 再次确认安装。

第二步 · 开启完全信任（关键）

3. 设置 → 通用 → 关于本机 → 证书信任设置 → 找到 XinQianYun Notary → 打开「启用完全信任」开关。

最常见失败原因：只做了第一步、漏掉第二步。iOS 对用户安装的根证书默认不信任，必须手动开启「完全信任」，否则访问时仍会报证书无效。

五、验证是否生效

3
两种验证方式

方式 A · 浏览器目视检查

打开 https://localhost:8090/index.html，地址栏左侧应显示锁形图标，且不再出现「不安全」警告。点击锁图标可查看证书颁发者与有效期。

方式 B · 命令行校验

# 使用证书作为信任锚访问，成功返回 HTML 即表示证书链有效
curl --cacert /workspace/certs/cert.pem https://localhost:8090/

# 仅检查状态码
curl --cacert /workspace/certs/cert.pem -o /dev/null -w "HTTP %{http_code}\n" https://localhost:8090/
预期输出：HTTP 200。若返回 SSL certificate problem，说明证书未被信任或访问地址不在 SAN 中。

六、常见问题排查

现象原因与处理
仍然提示「不安全」 证书装错存储位置。Windows 必须装进「受信任的根证书颁发机构」；iOS 必须开启「完全信任」。删除后重新安装。
ERR_CERT_AUTHORITY_INVALID 同上，根证书未被信任。检查证书是否已过期，或是否安装到了「个人」存储。
证书名称不匹配 / NET::ERR_CERT_COMMON_NAME_INVALID 访问地址不在证书 SAN 内。按 4.2 节重新生成包含该 IP 或域名的证书。
ERR_CONNECTION_REFUSED 服务未启动或端口被占。执行 ss -tlnp | grep 8090 检查；如端口被占用先释放再启动。
摄像头 / 麦克风无法调用 浏览器仅在安全上下文（HTTPS 或 localhost）下允许摄像头。请确认访问协议是 https://，而非 http://。
Chrome 提示「您即将访问的网站包含恶意软件」 自签证书 + 非 443 端口偶发误报，可忽略或在浏览器设置中将该地址加入白名单。
证书过期 2027-11-02 后失效，按第七节重新生成。

七、证书信息与续期

自签证书有效期 1 年，到期前需重新生成（重新生成后各设备需重新安装并信任新证书）：

cd /workspace

# 备份旧证书
cp certs/key.pem  certs/key.pem.bak.$(date +%Y%m%d)
cp certs/cert.pem certs/cert.pem.bak.$(date +%Y%m%d)

# 生成新证书（本机使用）
openssl req -x509 -newkey rsa:2048 \
  -keyout certs/key.pem \
  -out certs/cert.pem \
  -days 365 -nodes \
  -subj "/CN=localhost/O=XinQianYun Notary" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

# 重启服务使新证书生效
pkill -f "node server.js"; nohup node server.js > /tmp/notary-https.log 2>&1 &

查看当前证书详情：

openssl x509 -in /workspace/certs/cert.pem -noout -subject -dates -ext subjectAltName

八、安全注意事项与后续升级

1. 私钥保密：key.pem 权限应为 600，不得提交到代码仓库、不得通过聊天工具传输、不得放入交付包。
2. 自签证书的定位：适合本机演示、内网试用与开发联调，不适合对外正式业务。公共 CA 证书才能让陌生用户无需任何配置即可安全访问。
3. 分发范围：只分发 cert.cer / cert.pem，并在分发说明中提示接收方核对 SHA-256 指纹。

升级为正式证书（拥有域名后）

项目已预置签发脚本 scripts/issue-cert.sh，通过阿里云 DNS-01 挑战申请 Let's Encrypt 证书：

# 方式一：命令行参数
./scripts/issue-cert.sh notary.yourdomain.com <Ali_Key> <Ali_Secret>

# 方式二：环境变量
Ali_Key=xxx Ali_Secret=yyy CERT_DOMAIN=notary.yourdomain.com ./scripts/issue-cert.sh

# 方式三：交互式（Secret 不回显）
./scripts/issue-cert.sh

脚本会自动完成：DNS 验证 → 签发 → 备份旧证书 → 写入 /workspace/certs/ → 重启服务。由于 server.js 始终从该目录读取证书，应用代码无需任何改动。

前提：域名已在阿里云 DNS 解析托管，RAM 账号具备 AliyunDNSFullAccess 权限。example.com 等保留域名无法签发，必须使用真实自有域名。
