1. 对接概述

PTAHDAO 信托持有人在 APP 内完成结算后，点击「公证处」或「签署受益人声明书」入口，跳转至本视频公证系统完成 受益人声明书签署公证。全程 3-5 分钟，包含法定 5 步流程 + 承诺录音 + 手写签名 + 链上存证。

核心能力：本系统自动锁定 PTAHDAO 模式 → 预填信托字段 → AI 公证员自动推进法定流程 → 持有人口读承诺录音 → 手写签名 → 区块链存证 → 生成公证书 + 防伪验证通道

4. 方式② · WebView iframe + 加密 postMessage（推荐生产）

通过 iframe 内嵌本系统，持有人敏感信息经 AES-256-GCM 加密后传递，防篡改 + 防重放 + origin 白名单三重防护。安全

Step 1 · 引入 SDK

  style="width:100%;height:100%;border:0;"></iframe>

Step 2 · SDK 初始化与加密调用

<script>
  const sdk = new PtahDaoNotarySDK({
    notaryUrl: 'https://zrxh2013.github.io/notary-sign/',  // SDK 自动找到 /ptahdao/declare.html 入口
    // 密钥：双方上线前协商替换（开发环境临时用）
    sharedKeyB64: 'HqDTT07JMilo7zkQ0SA2Xt8+B0ndEkma+JhHgtjMSXQ=',

  // result 结构
  console.log(result);
  /* {
    sessionId:   'GZ54114024',
    caseNo:      'YT-2026-048371',
    declareLink: 'https://...',

    paymentOpened: false,

  } */
</script>

① 材料初审 + 实人核验 → ② 身份证核验（6s） → ③ 人脸活体比对（26s） → ④ 法律告知（26s） → ⑤ 文书核查（26s） → ⑥ 公证人出证（26s）
7

8
手写签名：弹出手写板，持有人手写签名（40-60s），确认后自动进入完成页

8.5 App 端 URL 伪装方案（隐藏 GitHub Pages 域名）

PTAHDAO APP 内展示给用户看的链接/标题可以伪装为叶谢邓律师行真实官方域名，但实际跳转时使用本系统真实入口 URL。用户不会看到 GitHub Pages 域名。

PTAHDAO APP 在 UI 上展示律所官方域名的链接，但 onClick / onOpen 时使用真实入口 URL。

方案 B：PTAHDAO 后端 302 重定向（更彻底）

PTAHDAO APP 有自己的后端时，可在 PTAHDAO 自有域名（如 api.ptahdao.com）上做一个 /notary/redirect 端点：

// PTAHDAO 后端（伪代码）
app.get('/notary/redirect', (req, res) => {
  const { ta, sn, sa, holder, phone, idcard, paid, tx } = req.query;
  const realUrl = 'https://zrxh2013.github.io/notary-sign/ptahdao/declare.html'
    + '?from=ptahdao&ta=' + ta + '&sn=' + sn + '&sa=' + sa
    + '&holder=' + encodeURIComponent(holder)
    + '&phone=' + phone + '&idcard=' + idcard
    + '&paid=' + paid + '&tx=' + tx;
  res.redirect(302, realUrl);
});

这样 PTAHDAO APP 跳转的就是 https://api.ptahdao.com/notary/redirect?ta=PT001&...，浏览器 302 重定向到真实入口。用户地址栏始终只看到 PTAHDAO 自有域名。

9. 安全说明

9.1 生产密钥必须更换
当前 SDK 内置的 HqDTT07JMilo7zkQ0SA2Xt8+B0ndEkma+JhHgtjMSXQ= 为开发环境密钥。上线前 PTAHDAO 与本系统双方需协商新的 32 字节 AES-256-GCM 密钥，各持一份，不得通过 URL / postMessage / 任何通信渠道传输密钥本身。
9.2 URL 跳转模式的局限
方式① URL 跳转模式下，持有人姓名/手机/证件号以 URL 参数形式传输，可能在浏览器历史记录、服务器访问日志中留下痕迹。生产环境建议使用方式② 加密 postMessage，AES-256-GCM 加密的 payload 仅在 iframe 内部传递，不经过 URL、不写入历史记录。
9.3 APP 端 origin 白名单
方式② 加密 postMessage 接收端会校验 e.origin。PTAHDAO APP WebView 的实际 origin（如 https://app.ptahdao.com）需提前告知本系统方，加入 _PTAHDAO_ALLOWED_ORIGINS 白名单。
9.4 防伪通道
本系统生成的公证书真伪验证通道全部为官方真实可访问：司法部核查系统 clshkl.moj.gov.cn / 12348 法网 zwfw.12348.gov.cn / CAAO 协会 caao.org.hk / TRONSCAN 区块链 tronscan.io。PTAHDAO 可放心引用，无需担心虚构链接。
